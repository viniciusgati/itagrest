# Test Design: Story 0.US000

Date: quarta-feira, 15 de abril de 2026
Designer: Quinn (Test Architect)

## Test Strategy Overview

- **Total test scenarios:** 10
- **Unit tests:** 4 (40%)
- **Integration tests:** 3 (30%)
- **E2E tests:** 3 (30%)
- **Priority distribution:** P0: 5, P1: 4, P2: 1

## Test Scenarios by Acceptance Criteria

### AC1: Detecção de Estado (Redirect/Expose endpoint)

| ID           | Level       | Priority | Test                                | Justification                                  |
| ------------ | ----------- | -------- | ----------------------------------- | ---------------------------------------------- |
| 0.US000-INT-001 | Integration | P0       | Bootstrap status returns 'ready' when DB empty | Critical for initial system activation         |
| 0.US000-INT-002 | Integration | P0       | Bootstrap status returns 403 when DB has users | **SECURITY**: Prevent unauthorized setup access |
| 0.US000-E2E-001 | E2E         | P1       | Auto-redirect to /setup on empty DB | Validates "Zero Attrition" UX goal             |

### AC2: Criação de Conta (Form & Validation)

| ID           | Level       | Priority | Test                                | Justification                                  |
| ------------ | ----------- | -------- | ----------------------------------- | ---------------------------------------------- |
| 0.US000-UNIT-001 | Unit        | P1       | Validate input formats (Email, Name) | Basic data integrity                           |
| 0.US000-UNIT-002 | Unit        | P0       | Password minimum length (8 chars)    | Security baseline                              |
| 0.US000-E2E-002 | E2E         | P1       | Instant validation for password mismatch | UX Feedback requirement                        |

### AC3: Segurança (Hashing)

| ID           | Level       | Priority | Test                                | Justification                                  |
| ------------ | ----------- | -------- | ----------------------------------- | ---------------------------------------------- |
| 0.US000-UNIT-003 | Unit        | P0       | Password hashing using BCrypt       | **SECURITY**: Prevent plain-text storage       |

### AC4: Responsividade

| ID           | Level       | Priority | Test                                | Justification                                  |
| ------------ | ----------- | -------- | ----------------------------------- | ---------------------------------------------- |
| 0.US000-E2E-003 | E2E         | P2       | Layout usable on mobile (375px)     | Mobile-First requirement                       |

### AC5: Transição (Auto-login/Redirect)

| ID           | Level       | Priority | Test                                | Justification                                  |
| ------------ | ----------- | -------- | ----------------------------------- | ---------------------------------------------- |
| 0.US000-INT-003 | Integration | P0       | Disable bootstrap immediately after setup | **SECURITY**: Atomic transition to secure state |
| 0.US000-UNIT-004 | Unit        | P1       | Session creation logic after bootstrap | Ensures seamless redirect                      |

## Risk Coverage

- **RISK-SEC-01 (Unauthorized Setup):** Mitigated by `0.US000-INT-002` and `0.US000-INT-003`.
- **RISK-DATA-01 (Plain-text Password):** Mitigated by `0.US000-UNIT-003`.
- **RISK-UX-01 (Setup Friction):** Mitigated by `0.US000-E2E-001`.

## Recommended Execution Order

1. **P0 Unit tests** (Password hashing, length validation)
2. **P0 Integration tests** (Bootstrap status and shutdown logic)
3. **P1 E2E tests** (Happy path journey with redirect)
4. **P2 tests** (Responsiveness)
